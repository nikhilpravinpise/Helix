# Overnight audit, 2026-10-05

What was done while Vraj slept, what was found, and what is waiting on
him. Every bug listed as fixed was reproduced first and has a test that
failed before the fix; each fix is its own commit.

## How the audit ran

Four Sonnet 5.5 agents each read one area and reported findings with a
concrete failure scenario. They could read code and run tests or small
scripts against SQLite and in-memory fakes, but could not edit files,
touch git, Docker, Postgres or the network. Every finding was then
checked again by reproducing it before anything was changed.

| Area | Scope |
|---|---|
| Safety and execution | `agent/`, Kubernetes, GitHub and Jenkins write paths |
| Events and state | `events/`, `state/` |
| Integrations and API | `integrations/`, `helix/api.py`, `helix/cli.py`, `helix/config.py`, `helix/llm.py`, `ui/` |
| Benchmark | `benchmark/`, scenario YAMLs |

## Findings

Status: **fixed** (commit named), **parked** (FOLLOWUPS item named, with
why), **not a bug** (with why), or **queued** (not reached yet).

### Events and state

| # | Finding | Status |
|---|---|---|
| E1 | A newly opened PR joins an open *recovery* incident on the same service token, so it is never reviewed | **fixed** b7605e8: an event carrying a PR joins only an incident sharing its PR, branch or commit |
| E1b | A crash joins an open *change* incident on the same service token, so no recovery incident opens | parked, FOLLOWUPS #18 (design question: change incidents are meant to absorb deploy failures) |
| E2 | A PR closed and reopened with the same head sha gets the same event id and is dropped as a duplicate | **fixed** b0b5e73: reopens are reported as `reopened` with their own id |
| E3 | A pod that goes not-Ready, recovers, and goes not-Ready again gets the same event id and is dropped | **fixed** eeaabff: the id includes the Ready condition's transition time |
| E4 | Adapters stamp events with ingest time, not the vendor's time, so the correlation window measures the wrong thing | parked, FOLLOWUPS #18 |
| E5 | The watchers mark a change as seen before publishing it, so a failed publish loses it | **fixed** 9a4aeef: state is saved only after the poll's events are published |

### Integrations and API

| # | Finding | Status |
|---|---|---|
| I1 | One 429 or 401 puts the only LLM key on a one-hour blacklist; every later call fails without trying | **fixed** 3fe23b5: a set-aside key only moves down the order; with none ready the soonest-back key is tried |
| I2 | Outbox rows become `sent` only when the caller's whole transaction commits, so a later failure re-sends everything already posted | **fixed** 2026-10-07: commit per row, rows claimed with `FOR UPDATE SKIP LOCKED` |
| I3 | PR titles and other outside text go into Slack messages unescaped, so a title can ping `@channel` or plant a fake link | **fixed** d0eb2e8: all outside text is mrkdwn-escaped in cards, thread lines and fallback text |
| I4 | Any Slack user, or any `--actor` on the CLI/API, can decide a review or approval; nothing checks they are the named reviewer or owner | **fixed** 30af9a1: owners approve, the requested reviewer reviews, the author decides neither |
| I5 | A page deleted in Notion comes back as archived, not missing, so it is never recreated and its updates fail | parked, FOLLOWUPS #18 (not yet reproduced) |
| I6 | Minor: `helix sync` exits 0 with failed rows; `helix review` exits 0 on a failed resume; Slack review clicks use the wrong timeout setting | **fixed** 7f00c9a |

### Safety and execution

| # | Finding | Status |
|---|---|---|
| S1 | A triage or review step that hits `HELIX_STEP_TIMEOUT` is re-run forever: the run never ends and threads pile up | **fixed** fbef859: those branches check for a failed step before re-sending to the node |
| S2 | A fix PR to the Secret manifest skips the approval gate when its path is written `sandbox/payment-api/./k8s/03-secret.yaml` or with `//` | **fixed** 20b481f: fix PR paths are normalized before policy rates them |
| S3 | Nothing ties a write's deployment or namespace to the incident: `restart_deployment` on `kube-system/coredns` is allowed unapproved | **fixed** 11c4ffb: cluster writes outside a registered namespace need approval |
| S4 | Arm A's rules always target payment-api, whatever service the signal names | **fixed** a1480b6 |
| S5 | A human-approved write is recorded with no approver, because the execution gate re-decides without the evidence | **fixed** 60aa6b4: the gate returns the granted approval whenever one exists |

### Benchmark

| # | Finding | Status |
|---|---|---|
| B1 | `unsafe_executions` counts an unsafe action the policy *refused* as if it ran, so a working safety gate scores as unsafe | **fixed** 6170a0b: refused rows are left out of the unsafe count |
| B2 | `_drive` stops after the scripted approver decides a second time, so an approved action after a replan is never run and the arm scores a miss | **fixed** 868f48e: a decision counts as progress, as in the change drive |
| B3 | `xsys-runtime-missing-owner` (billing-worker, `NeverSeenReason`) replays payment-api crashloop evidence, so the LLM arms reason over the wrong service | parked, FOLLOWUPS #18 (not reproducible without LLM arms) |
| B4 | Root-cause matching is substring-based: `pr` matches "problem", and several faults' real text matches another fault's tokens, inflating LLM RCA | **fixed** 1659f04: tokens match at word starts, short tokens as whole words |
