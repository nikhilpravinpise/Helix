Autonomous DevOps, with a human in the loop

When something breaks, Helix works out why and fixes it.

Helix watches your CI, deployments and pull requests, plans a fix, checks that it is safe, carries it out and verifies that it worked. Anything risky waits for a person, and it never merges its own code.

How it works

One loop from signal to verified fix.

  1. 01

    Signal

    A failed build, a bad deploy or a new pull request arrives and is grouped into a single incident.

  2. 02

    Diagnose

    Helix collects real evidence, such as build logs and cluster state, and forms a hypothesis about the cause.

  3. 03

    Plan

    It picks one bounded action from a fixed catalogue: restart, roll back, scale, rerun a pipeline or open a fix pull request.

  4. 04

    Validate and gate

    The plan is validated, then a safety policy decides whether it may run alone or must wait for approval.

  5. 05

    Execute

    The action runs through a typed executor, which checks the same policy a second time before it writes anything.

  6. 06

    Verify

    Helix checks that the system actually recovered, and escalates to a person when it did not.

Integrations

Works where your team already is.

Connect each one from the dashboard with OAuth or an app install.

Slack

Each incident gets a thread. Approve or reject a risky action with a button, right where the team is talking.

Jira

Work items are created and kept in step with the incident, so the ticket always matches what Helix recorded.

GitHub

The Helix GitHub App opens fix pull requests on the repositories you choose. A person reviews and merges them.

Safety

Built so a wrong guess cannot reach production.

  • A person approves risky actions

    High-risk actions, and any write in production, wait for an owner of the service to approve. Nobody approves their own change.

  • Helix never merges its own code

    It opens fix pull requests. Reviewing and merging stays with your team.

  • Least privilege

    The model never gets a shell. It chooses from a fixed catalogue of typed actions, and GitHub access is limited to the repositories you install the app on.

  • Every decision on record

    Evidence, plan, approval and outcome are stored with who, when and why, and you can read the full trail for any incident.

  • Tokens encrypted at rest

    Connection tokens are encrypted before they reach the database.
